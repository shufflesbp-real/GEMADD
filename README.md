# GEMADD  
# GEMADD: A Graph-based Explainable Multimodal Framework for Disease Diagnosis

GEMADD is a graph-based, explainable multimodal framework for medical disease diagnosis that integrates textual symptoms, visual evidence, medical knowledge graphs, and assistance from Large Language Models (LLMs) and Vision-Language Models (VLMs).

LLMs and VLMs are used strictly for understanding and structuring textual and visual inputs. The final diagnosis is **not** generated by any LLM. Instead, all diagnostic decisions are produced via transparent, graph-based reasoning over a unified medical knowledge graph, ensuring full explainability.

## Installation

### Clone the Repository

Clone the GEMADD repository and move into the project directory:

git clone https://github.com/shufflesbp-real/GEMADD.git  
cd GEMADD

---

### Install Requirements

Install all required Python dependencies using:

pip install -r requirements.txt

This installs all core dependencies required to run the GEMADD framework, including libraries for graph processing, multimodal embeddings, and medical NLP.

---

### Install SRWR Module

GEMADD uses the Supervised Random Walk with Restart (SRWR) module for graph-based disease ranking.

Clone and install the SRWR repository:

git clone https://github.com/jinhongjung/srwr.git  
cd srwr  

Remove conflicting dependencies and install the remaining requirements:

grep -v "numpy" requirements.txt | grep -v "scipy" > modified_requirements.txt  
pip install -r modified_requirements.txt

Ensure that the `srwr` module is accessible in your Python path before running GEMADD.

## Medical Knowledge and Entity Mapping

GEMADD relies on standardized medical entity grounding using the **UMLS Metathesaurus**.

Users must independently obtain and install the following external resources:
- UMLS Metathesaurus (https://www.nlm.nih.gov/research/umls)
- QuickUMLS
- SciSpacy medical language models

All medical entities, including symptoms, diseases, and clinical findings, are mapped to **UMLS Concept Unique Identifiers (CUIs)**.

A sample universal entity-mapping file is provided at:

data-files/sample_universal_mapping_quickumls.csv

This file illustrates the expected format for storing entity-to-UMLS mappings generated using QuickUMLS or SciSpacy and can be extended by users for their own datasets.

## Unified Knowledge Graph

GEMADD constructs a **Unified Knowledge Graph (UKG)** that integrates medical evidence from multiple sources to support explainable disease diagnosis.

The Unified KG combines:
- Disease–symptom relationships extracted from multiple datasets
- Statistical co-occurrence information
- Prior medical knowledge derived from curated resources

Due to the inclusion of proprietary and restricted data sources, the **complete Unified Knowledge Graph cannot be released publicly**.

To support reproducibility and understanding of the framework, the repository provides:
- Sample disease–symptom mappings
- Sample edge weights
- Sample prior statistics and counts

These files are located in the `data-files/` directory and demonstrate the structure, format, and usage of the Unified Knowledge Graph within the GEMADD pipeline.

## LLM and VLM Usage

GEMADD incorporates **Medical Large Language Models (LLMs)** and **Vision-Language Models (VLMs)** as assistive components for multimodal input understanding.

### Models Used
- Medical LLMs: Baichuan (8B)
- Vision-Language Models: Qwen-2-VL (for visual symptom extraction)

### Role of LLMs and VLMs

LLMs and VLMs are used to:
- Parse and structure free-text patient symptom descriptions
- Extract clinically relevant visual symptoms from medical images
- Normalize and standardize medical terminology before graph insertion

LLMs and VLMs **do not perform disease prediction or ranking**. Their role is limited to perception and structuring of multimodal inputs.

All final diagnoses are computed using **graph-based reasoning over the Unified Knowledge Graph**, ensuring interpretability and traceability.

### Running on ES-MMD

To run GEMADD on the ES-MMD dataset:
- Prepare the required ES-MMD data files
- Update dataset and output paths in `config.py`

Execute the pipeline using:
cd esmmd-diagnosis  
python main.py
# GEMADD
###### Create Disease-Symptom Mapping

Create `disease_symptom_esmmd.json` containing all possible symptoms for each disease.

**Required Format:**
```
{
"Acne": [
"skin rash",
"acne or pimples",
"skin lesion",
"abnormal appearing skin"
],
"Diabetes": [
"increased thirst",
"frequent urination",
"fatigue"
]
}
```
**Key Format Rules:**
- **Keys:** Disease names (exact match with ground_truth values)
- **Values:** List of all possible symptoms (lowercase)

**Generation Method:**
- Aggregate all symptoms associated with each disease across the entire dataset
- Remove duplicates
- Ensure symptom names are in lowercase

Refer to `sample_disease_symptom_esmmd.json` in the repository for the complete format.

#### Step 2: Prepare Data Files

Ensure all data files are in place:
- ES-MMD dataset files (train/test JSON, symptom co-occurrence, disease-symptom mapping)
- VGG19 embeddings (`vgg19_image_embeddings.npz`)
- Image files in `/all_images/train/` and `test/`

Update paths in `config.py`:

#### Step 4: Verify SRWR Module

Ensure SRWR module is accessible otherwise adjust the imports accordingly.

#### Step 5: Run Diagnosis System

```bash
cd esmmd-diagnosis
python main.py
```

Results will be saved to the path specified in `RESULTS_OUTPUT_PATH` in `config.py`.

## Explainability and Transparency

GEMADD is explicitly designed to support **transparent and explainable medical diagnosis**.

Explainability is achieved through:
- Explicit symptom–disease relationships encoded in the knowledge graph
- Graph-based disease ranking using probabilistic algorithms
- Traceable aggregation of evidence from text and images

Even though LLMs and VLMs are used for multimodal understanding, **all diagnostic reasoning steps remain observable and interpretable**, enabling auditability and clinical trust.
